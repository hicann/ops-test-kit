# 命令行总览

```
python3 -m ttk {kernel,aclnn,e2e,info,list} [选项]
```

| 子命令 | 用途 |
|--------|------|
| `kernel` | AscendC算子内核编译 + NPU执行 + 精度比对 |
| `aclnn` | aclnn\* C API调用 + 精度比对 |
| `e2e` | PyTorch框架API端到端测试（支持NPU/MLU/CPU） |
| `info` | 查询本机Ascend NPU设备信息 |
| `list` | 预览CSV中的测试用例列表 |

查看版本：

```shell
python3 -m ttk -v
```

查看帮助：

```shell
python3 -m ttk kernel --help
python3 -m ttk aclnn --help
python3 -m ttk e2e --help
```

# 快速开始

## Kernel模式

```shell
# 默认动态编译模式运行MatMulV3算子
python3 -m ttk kernel -i examples/case_store/kernel/mat_mul_v3.csv

# 运行Add算子（动态 shape 编译）
python3 -m ttk kernel -i examples/case_store/kernel/add.csv -d

# 仅编译不执行
python3 -m ttk kernel -i examples/case_store/kernel/add.csv --co
```

## ACLNN模式

```shell
python3 -m ttk aclnn -i examples/case_store/aclnn/aclnn_cat.csv
python3 -m ttk aclnn -i examples/case_store/aclnn/aclnn_add.csv
```

## E2E模式

```shell
# 自动按配置 hardware segment 选择可用后端
python3 -m ttk e2e -i examples/case_store/e2e/torch_add.csv

# 强制 CPU 后端
python3 -m ttk e2e -i examples/case_store/e2e/torch_add.csv --cpu
```

## E2E/ACLNN/Kernel两阶段执行

输入和 CPU Golden 可先在 prepare 环境生成，再迁移到目标设备执行：

```shell
# prepare：不执行目标API和compare
python3 -m ttk e2e -i cases.csv --plugin /path/to/assets \
  --no-prof --dump in,golden --dump-format bin \
  --manual-data-dirs /data/manual

# replay：恢复输入和Golden，只执行目标API与compare
python3 -m ttk e2e -i cases.csv --plugin /path/to/assets \
  --manual-data-dirs /data/manual
```

ACLNN 使用相同参数；无卡 prepare 环境无法探测 SoC 时增加
`--plat=<目标SoC>`。完整目录规则、typed data 文件校验和参数约束参见
[手工数据准备与回放](./手工数据准备与回放.md)。

Kernel 使用相同的阶段选择参数，并保留原执行模式参数：

```shell
python3 -m ttk kernel -i kernel_cases.csv --plugin /path/to/kernel_assets \
  -d=false -c=false -b=release \
  --no-prof --dump in,golden --dump-format bin \
  --manual-data-dirs /data/kernel_manual

python3 -m ttk kernel -i kernel_cases.csv --plugin /path/to/kernel_assets \
  -d=false -c=false -b=release \
  --manual-data-dirs /data/kernel_manual
```

Kernel 单独使用 `--no-prof` 时仍是原 dry-run；只有精确组合
`--no-prof --dump in,golden` 才进入 prepare。`--compile-only` 不能与任一手工数据阶段
组合。

# 用例筛选

| 参数 | 缩写 | 说明 | 示例 |
|------|------|------|------|
| `--testcase` | `-t` | 按用例名筛选（逗号分隔） | `-t add_01,add_02` |
| `--testcase-index` | `--ti` | 按用例索引筛选 | `--ti=1,3,5` 或 `--ti=1-10` |
| `--testcase-count` | `--tc` | 随机选取N个用例 | `--tc=10` |
| `--operator` | `--op` | 按算子名筛选 | `--op add,mat_mul_v3` |
| `--exclude-operator` | `--no-op` | 排除算子名 | `--no-op concat_d` |
| `--priority` | | 按优先级筛选 | `--priority=1-3` |
| `--rerun` | | 重跑失败项 | `--rerun=precision_status` |

示例：

```shell
# 按名称运行指定用例
python3 -m ttk kernel -i cases.csv -t add_01,add_02

# 按索引范围运行
python3 -m ttk kernel -i cases.csv --ti=1-10

# 按算子名筛选
python3 -m ttk kernel -i cases.csv --op add,mat_mul_v3

# 按优先级筛选
python3 -m ttk kernel -i cases.csv --priority=1-3

# 随机选取10个用例
python3 -m ttk kernel -i cases.csv --tc=10
```

# 设备与并行

| 参数 | 缩写 | 说明 | 默认值 |
|------|------|------|--------|
| `--device` | `--dev` | 使用设备数量 | 全部 |
| `--device-whitelist` | | 设备白名单 | 无 |
| `--device-blacklist` | | 设备黑名单 | 无 |
| `--process-count` | `--pc` | 每张卡进程数 | 1 |
| `--platform` | `--plat` | SoC版本 | 自动检测 |
| `--proc-timeout` | | 单用例超时（秒） | 0（不限） |
| `--limit` | `-l` | 用例内存上限（GB），输入输出字节数之和超过则跳过 | 30 |

示例：

```shell
# 使用2张卡
python3 -m ttk kernel -i cases.csv --dev 2

# 指定设备白名单
python3 -m ttk kernel -i cases.csv --device-whitelist=0,1

# 每张卡启动2个进程
python3 -m ttk kernel -i cases.csv --pc=2

# 指定SoC平台
python3 -m ttk kernel -i cases.csv --plat Ascend910B2

# 设置单用例超时
python3 -m ttk kernel -i cases.csv --proc-timeout=300

# 跳过输入输出总内存超过10GB的用例
python3 -m ttk kernel -i cases.csv -l 10
```

# 精度控制

| 参数 | 说明 | 可选值 | 默认值 |
|------|------|--------|--------|
| `--compare` | 精度对比方法 | `close`/`stat_rel_err`/`cosine`/`binary`/`requant`/`cross_check` | Spec.tolerance 路由（需 `--plugin`），否则 `stat_rel_err` |
| `--input-dist` | 输入数据分布 | `uniform`/`normal` | `uniform` |
| `--seed` | 随机种子（可复现） | 整数 | 随机 |
| `--golden-mode` | Golden生成模式 | `Enable`/`Disable`/`Promote` | `Enable` |

示例：

```shell
# 使用余弦相似度比对
python3 -m ttk kernel -i cases.csv --compare cosine

# 使用二进制精确比对
python3 -m ttk kernel -i cases.csv --compare binary

# 使用正态分布生成输入数据
python3 -m ttk kernel -i cases.csv --input-dist normal

# 固定随机种子
python3 -m ttk kernel -i cases.csv --seed 42

# 关闭Golden生成（仅编译+执行）
python3 -m ttk kernel -i cases.csv --golden-mode Disable
```

> 精度对比方法的详细说明请参考[结果分析](./结果分析.md)

# 调试与诊断

| 参数 | 说明 | 示例 |
|------|------|------|
| `--dump` | Dump数据：`full`/`in`/`out`/`golden` | `--dump full` |
| `--dump-format` | Dump格式：`bin`/`npy`/`pt`/`print` | `--dump-format npy` |
| `--dump-on-fail` | 精度失败时Dump全部数据 | `--dump-on-fail` |
| `--manual-data-dirs` | prepare输出目录或replay有序搜索目录 | `--manual-data-dirs /data/op` |
| `--single-log` | 每个用例独立日志文件 | `--single-log` |
| `--plugin` | 外部插件路径 | `--plugin /path/to/plugin.py` |
| `--validate` | 仅校验CSV用例格式，不执行编译、输入生成、Golden生成等流程 | `--validate` |

示例：

```shell
# 失败时自动Dump数据
python3 -m ttk kernel -i cases.csv --dump-on-fail

# Dump输入和Golden到npy文件
python3 -m ttk kernel -i cases.csv --dump in,golden --dump-format npy

# 每个用例独立日志
python3 -m ttk kernel -i cases.csv --single-log

# 加载自定义插件
python3 -m ttk kernel -i cases.csv --plugin /path/to/my_golden.py
```

# 结果输出

| 参数 | 缩写 | 说明 | 示例 |
|------|------|------|------|
| `--output` | `-o` | 输出结果CSV路径 | `-o results.csv` |
| `--title` | | 自定义输出列 | `--title testcase_name,precision_status` |
| `--csv-preserve` | | 保留原始CSV表头 | `--csv-preserve` |

示例：

```shell
# 输出结果到CSV文件
python3 -m ttk kernel -i cases.csv -o results.csv

# 保留原始CSV表头
python3 -m ttk kernel -i cases.csv -o results.csv --csv-preserve

# 自定义输出列
python3 -m ttk kernel -i cases.csv -o results.csv --title testcase_name,op_name,precision_status
```

# Kernel编译控制

| 参数 | 缩写 | 说明 | 默认值 |
|------|------|------|--------|
| `--dynamic` | `-d` | 动态 shape 编译；`-d false` 关闭 | **开启** |
| `--const` | `-c` | 静态 shape 编译 | 关闭 |
| `--binary` | `-b` | 二进制模式；`-b release` 使用发布内核 | 关闭 |
| `--compile-only` | `--co` | 仅编译不执行 | 关闭 |
| `--no-prof` | | Kernel dry-run；与精确的 `--dump in,golden` 组合时进入手工数据 prepare | 关闭 |
| `--compile-opts` | | 编译选项（KEY=VALUE格式，可多次指定） | 无 |
| `--tiling-run` | `--tr` | Tiling运行次数 | 3 |
| `--reuse-hbm` | | 每个用例默认下发3次到NPU执行，复用同一块HBM内存以使能L2 Cache | 关闭 |
| `--reserve-hbm` | | 预留HBM内存（MB） | 无 |
| `--clear-atomic` | | 强制在算子执行前清零输出和workspace | 关闭 |
| `--clear-ub` | | 执行前将UB填充为指定值（默认清零） | 关闭 |
| `--clear-l1` | | 执行前将L1填充为指定值（默认清零） | 关闭 |
| `--simt-ub` | | SIMT 模式 UB 大小 | 无 |
| `--simt-stack-dcu` | | SIMT 模式 DCU 栈大小 | 无 |
| `--force-block-dim` | | 强制指定 block_dim | 无 |

示例：

```shell
# 动态 shape 编译
python3 -m ttk kernel -i cases.csv -d

# 关闭动态 shape 编译
python3 -m ttk kernel -i cases.csv -d false

# 静态 shape 编译
python3 -m ttk kernel -i cases.csv -c

# 使用二进制发布内核
python3 -m ttk kernel -i cases.csv -b release

# 仅编译不执行
python3 -m ttk kernel -i cases.csv --co

# 禁用Profiling
python3 -m ttk kernel -i cases.csv --no-prof

# 编译选项
python3 -m ttk kernel -i cases.csv --compile-opts op_debug_config=oom,dump_cce --compile-opts enable_deterministic_mode=1

# 多次执行间复用HBM（使能L2 Cache）
python3 -m ttk kernel -i cases.csv --reuse-hbm
```

# E2E专用参数

> E2E 模式由统一的 Backend 抽象层驱动（`framework_api/backends/`），各后端共享同一套用例与精度比对逻辑。CPU 后端可作为 Golden 计算源。后端按配置 hardware segment（`yaml` 的 `frameworks.torch.<seg>`）自动选择可用后端，`--cpu` 强制 CPU 后端。

# ACLNN专用参数

ACLNN 子命令复用通用参数，无专属选项。

# 通用参数速查表

| 参数 | 缩写 | 说明 | 默认值 |
|------|------|------|--------|
| `--input` | `-i` | CSV用例文件路径（必填） | |
| `--output` | `-o` | 输出结果CSV路径 | 无 |
| `--seed` | | 随机种子 | 随机 |
| `--print` | | 打印摘要信息 | 开启 |
| `--no-memory-check` | | 跳过主机内存检查 | 关闭 |
| `--proc-no-reuse` | | 每个用例创建新进程 | 关闭 |
| `--task-prof` | | 任务级Profiling开关 | 开启 |
| `--po` / `--progress-output` | | 进度输出路径 | 无 |
| `--run` | | 执行次数 | 板端3次/模型1次 |
| `--warmup` | | Profiling前预热 | 开启 |
| `--npu-timeout` | | NPU执行超时（ms） | 无限制 |
